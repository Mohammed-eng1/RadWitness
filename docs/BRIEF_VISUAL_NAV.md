# BRIEF: طبقة الملاحة البصرية — Gemini Flash-Lite فوق التمشيط المنهجي

متابعة لـ RMS Rover v2. إضافة **رؤية حاسوبية سحابية** تُستدعى عند الحيرة (لا دورياً) لتفهم المشهد دلالياً وتوجّه المسار — مع بقاء التمشيط المنهجي أساساً يضمن التغطية الكاملة، والحساسات طبقةَ أمان تحت الكل.

**المنصة**: WAVE ROVER بلا إنكودرات (مؤكد) — لا موقع دقيق بالسنتيمتر. الملاحة تعتمد الجدران كمرجع + الجايرو المعاير + GPS للموقع الجغرافي.

---

## 0) الفلسفة الحاكمة — ثلاث طبقات، الأعلى لا يتحكم بأمان الأدنى

```
رؤية Gemini (بطيئة، عند الحيرة فقط، قد تنقطع) → تفهم المشهد وتقترح اتجاهاً
        ↓
تمشيط منهجي (خوارزمي، محلي، مجاني) → يضمن تغطية المنطقة كاملة
        ↓
سلامة تفاعلية (حساسات، فورية) → توقف وتفادٍ، تعمل دائماً بلا إنترنت
```

**قاعدة صلبة**: الرؤية **تقترح** والحساسات **تحمي**. لو أخطأ Gemini أو تأخّر أو انقطع الإنترنت → الروبوت يكمل بالتمشيط والحساسات بلا توقف. التغطية الكاملة أولوية على الاستكشاف الذكي (مصدر إشعاع قد يكون في زاوية لا تبدو مهمة بصرياً).

## 1) مزوّد الرؤية — `pi/ai/vision_nav.py`

- **النموذج**: `gemini-3.1-flash-lite` (الأرخص، الأسرع، مناسب للتعرّف البصري المتكرر). اسم النموذج **متغيّر واحد في config** للترقية بسطر (بديل أعلى: `gemini-3-flash`).
- **مستوى التفكير**: الحد الأدنى (المهمة وصف بصري لا استدلال عميق — يوفّر توكنات المخرجات).
- **المفتاح في `secrets.py` فقط** (مستثنى من git). تحقق من الرصيد والحدود.
- **التطوير على الطبقة المجانية** (Google AI Studio) أولاً لضبط البرومت، ثم التحويل للمدفوع.
- دقة الصور منخفضة (مثلاً 512px) لتقليل التكلفة والزمن.
- **مهلة وحماية**: كل استدعاء بمهلة (افتراضي 12 ثانية)؛ فشل/انقطاع/رد غير صالح → تُسجَّل ملاحظة ويكمل الروبوت بالمنطق المحلي.
- عدّاد استدعاءات + تكلفة تقديرية تُعرض في الواجهة (وعي بالرصيد).

## 2) محفّزات الاستدعاء — بذكاء لا دورياً

استدعِ الرؤية **فقط** عند إشارة حيرة حقيقية:

1. **الصندوق مقابل الجدار (المحفّز الرئيسي)**: الألترا سونيك يرى عائقاً ثابتاً بين `VISION_TRIGGER_MIN_CM` و`MAX_CM` (افتراضي 40-80 سم)، الروبوت يقترب قليلاً؛ إن بقيت المسافة "سطحاً عريضاً" بلا انفراج → استدعِ الرؤية: **"هل هذا جدار الغرفة (نمشي بمحاذاته) أم عائق منفصل (نلتف حوله لتغطية ما خلفه)؟"**
2. **تكرار التفادي**: ≥3 تفاديات في منطقة صغيرة خلال زمن قصير (علامة حصار) → استدعِ الرؤية لإيجاد مخرج.
3. **دخول منطقة جديدة**: بعد اجتياز مدخل/فتحة → لقطة واحدة لفهم المكان الجديد.
4. **قراءة غامضة**: `quality` الألترا سونيك منخفض باستمرار (سطح ماص/مائل) → الرؤية تحسم.
5. **طلب المستخدم اليدوي**: زر "حلّل المشهد".

**مانع التكرار**: لا تستدعِ الرؤية لنفس الموقف مرتين خلال `VISION_COOLDOWN_S` (افتراضي 20 ثانية) — يمنع استنزاف الرصيد في نفس البقعة.

## 3) المسح البصري 360° — عند الحصار أو التقاطع

عند الحاجة لقرار اتجاه (طريق مسدود، تقاطع، حصار):

1. الروبوت يلتقط صورة أمامه، يلفّ `SCAN_STEP_DEG` (افتراضي 45°) بالجايرو، يلتقط أخرى... حتى يجمع **`SCAN_SHOTS` صور** (افتراضي 4، أقصى 8) تغطي المحيط.
2. ترسل كلها في **طلب واحد** لـGemini (أوفر من عدة طلبات) مع البرومت المنظّم (بند 4).
3. Gemini يقيّم كل اتجاه ويعيد الأفضل.
4. الروبوت يلفّ للاتجاه المختار (زاوية معلومة من ترتيب اللقطات) ويكمل.

**السلامة أثناء المسح**: كل لفّة عبر `turn_by_angle` المعاير (مع تجزئة >120° وتوقف بين المراحل). الحساسات نشطة طوال الوقت.

## 4) البرومت والمخرَج المنظّم (إلزامي)

Gemini ملزم بإخراج JSON فقط، وبقول "غير واثق" عند الغموض (لا تخمين):

**لسيناريو الصندوق/الجدار:**
```json
{
  "obstacle_type": "room_wall | separate_object | doorway | furniture | unclear",
  "can_pass_around": true,
  "pass_side": "left | right | none",
  "confidence": "low | medium | high",
  "reason": "وصف قصير"
}
```

**لمسح الاتجاهات (عدة صور):**
```json
{
  "directions": [
    {"index": 0, "openness": "open|partial|blocked", "hazard": "none|furniture|wall|dropoff", "note": ".."}
  ],
  "best_index": 2,
  "confidence": "medium",
  "reason": ".."
}
```

- البرومت يشدّد: "أنت عين ملاحة لروبوت أرضي. صف المساحة القابلة للمرور. لا تكشف إشعاعاً (غير مرئي)." **افصل هذا تماماً عن أي مهمة كشف إشعاع** — هذه ملاحة فقط.
- تحقّق صارم من صحة الـJSON قبل الاستخدام؛ رد فاسد → تجاهل واكمل محلياً.

## 5) التكامل مع التمشيط — الرؤية توجّه ولا تُلغي التغطية

- **الصندوق منفصل** (`separate_object`, `can_pass_around`): الروبوت يلتف من `pass_side` **ويعلّم المنطقة خلفه للتغطية** — لا يتركها. هذا يحل مشكلة "الصندوق يُحسب جداراً فتُهمل المنطقة خلفه".
- **جدار غرفة** (`room_wall`): يعامله حدّاً، يلتف ويكمل التمشيط بمحاذاته.
- **مدخل/فتحة** (`doorway`): يعلّمها كنقطة اهتمام؛ إن كان ضمن نطاق المهمة، يدخل المنطقة الجديدة ويمشّطها.
- **الملاحة لا تتجمّد بانتظار الرؤية**: عند عائق يوقف الروبوت أصلاً (منتظر) يُقبل الانتظار؛ خلاف ذلك يكمل بالحساسات والنتيجة تُطبَّق عند وصولها.
- قرار الرؤية يُسجَّل في الخلية/المنطقة المعنية وفي تقرير المهمة (صورة + قرار + سبب).

## 6) الواجهة

- **قسم الرؤية البصرية**: آخر صورة حُلّلت + قرار Gemini (النوع، الاتجاه، الثقة، السبب) مقروءاً.
- **عدّاد الاستدعاءات + التكلفة التقديرية** (وعي الرصيد) + آخر زمن استجابة.
- زر يدوي "حلّل المشهد الآن" + زر "مسح 360° بصري".
- سجل الأحداث يميّز قرارات الرؤية (بأيقونة كاميرا) عن قرارات الحساسات.
- **وضع عرض مسجّل** (`REPLAY_VISION`): يعيد تشغيل قرارات رؤية محفوظة مسبقاً لعرض بلا إنترنت/رصيد — حماية ليوم العرض.

## 7) معايير القبول

**محاكاة/ويندوز** (بصور اختبار ثابتة بدل كاميرا حقيقية):
- [ ] استدعاء الرؤية يحدث فقط عند المحفّزات، لا دورياً؛ مانع التكرار يعمل.
- [ ] رد Gemini صالح → يُطبَّق؛ رد فاسد/مهلة → يُتجاهل والروبوت يكمل بلا تعثر.
- [ ] `separate_object` → الروبوت يلتف ويعلّم ما خلفه للتغطية (لا يهمله).
- [ ] `room_wall` → يعامله حدّاً ويكمل التمشيط.
- [ ] قطع الإنترنت → لا استدعاءات، والملاحة تستمر بالحساسات، والواجهة تعرض "الرؤية غير متاحة".
- [ ] عدّاد الاستدعاءات والتكلفة يتحدّثان صحيحاً.
- [ ] selftest يبقى ناجحاً + اختبارات تحقّق الـJSON.

**عتاد** (بعد اكتمال الأساس):
- [ ] وضع صندوق مفرد أمام الروبوت → الرؤية تميّزه عن الجدار، والروبوت يلتف حوله ويغطي خلفه.
- [ ] الروبوت في زاوية محاصر → مسح 360° بصري يختار المخرج المفتوح.
- [ ] باب مفتوح مقابل جدار → الرؤية تميّز المدخل.
- [ ] استهلاك الرصيد معقول في جلسة مسح كاملة (سجّل عدد الاستدعاءات الفعلي).

نفّذ (1) المزوّد والتحقق أولاً واختبره بصور ثابتة، ثم (2) المحفّزات، ثم (3) المسح 360°، ثم (5) التكامل. توقف بعد كل بند بملخص. لا تلمس منطق كشف الإشعاع — هذه طبقة ملاحة منفصلة.
