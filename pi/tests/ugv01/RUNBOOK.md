# UGV01 — دليل التشغيل (RUNBOOK)

الترتيب هنا **إلزامي**: كل خطوة تفترض نجاح ما قبلها. لا تتقدّم بعد NO-GO
قبل معالجته. التفصيل الكامل لكل سكربت في `README.md` بجانب هذا الملف.

## الإعداد المثبت (قياس على العتاد، لا افتراض)

```
═══════════════════════════════════════════
الإعداد المثبت على العتاد (قياس، لا افتراض)
═══════════════════════════════════════════
UART      : UART4
Device    : /dev/ttyAMA4
TX        : GPIO8  → الدبوس 24
RX        : GPIO9  → الدبوس 21
Baudrate  : 115200 · 8N1 · بلا تحكم تدفق

/boot/firmware/config.txt:
  [all]
  enable_uart=1
  dtoverlay=disable-bt
  dtparam=uart0=on
  dtoverlay=uart4

ملاحظات موثقة:
- GPIO8/9 هما أصلاً SPI0 (CE0 و MISO) ⇒ ناقل SPI غير متاح
- I2C على الدبوسين 3 و5 محجوز للحساسات
- EEPROM: WAKE_ON_GPIO=0 و POWER_OFF_ON_HALT=1
  (كان GPIO3 يوقظ الراسبري بعد كل إطفاء)
- أول ردّ حقيقي من اللوحة:
  {"T":1001,"L":0,"R":0,"r":-0.11,"p":1.33,"y":179.89,
   "temp":46.67,"v":11.72}
```

**أثره على السكربتات**: البحث التلقائي عن المنفذ بالترتيب
`/dev/ttyAMA4` ← `/dev/serial0` ← `/dev/ttyUSB*` ← `/dev/ttyACM*`، و`--port`
يتجاوزه. إن غاب `ttyAMA4` يطبع كل سكربت تشخيصاً يذكر `dtoverlay=uart4`
والدبوسين 24 و21، وأي سقوط احتياطي إلى منفذ آخر **يُعلَن** — لأن `serial0`
على هذه الراسبري منفذ حيّ لكنه **ليس** وصلة اللوحة.

## قبل أي خطوة

1. **ترتيب التشغيل**: الروبوت أولاً ← انتظر ~5 ثوانٍ ← ثم الراسبري/الأوامر.
2. البطارية مشحونة (خطوة 6 تقيسها تحت الحمل؛ لا تقِس حركةً على بطارية منهكة).
3. لا برنامج آخر يفتح `/dev/ttyAMA4` (السيرفر الرئيسي متوقّف).

**رموز الخروج** في كل سكربت: `0` = GO · `1` = NO-GO · `2` = أُلغي/Ctrl+C.
آخر سطر في الخرج دائماً `GO` أو `NO-GO` وحده، وقبله سطر `السجل: …csv`.

**السجلّات** في `pi/tests/ugv01/logs/` (مستثناة من git — ترسلها يدوياً).

## الخطوة 0 — التحضير (مرة واحدة)

```bash
cd ~/RMS-Rover-v2 && git pull && git checkout ugv01 && git pull
source venv/bin/activate
pip install pyserial
ls -l /dev/ttyAMA4 && grep -n uart4 /boot/firmware/config.txt && groups | grep -c dialout
```

- **يفحص**: الفرع، الاعتماد الوحيد (pyserial)، وجود المنفذ، الإعداد، صلاحية `dialout`.
- **الروبوت**: لا يهم.
- **GO**: يظهر `/dev/ttyAMA4`، وسطر `dtoverlay=uart4`، والعدد `1`.
- **NO-GO**:
  - لا `/dev/ttyAMA4` ⇒ أضف `dtoverlay=uart4` تحت `[all]` في `/boot/firmware/config.txt` ثم `sudo reboot`.
  - العدد `0` ⇒ `sudo usermod -aG dialout $USER` ثم اخرج وادخل من جديد.
- **CSV**: لا شيء.

## الخطوة 8 — `test_slip` · الانزلاق: الإنكودر مقابل الجايرو ⚠ يحرّك

```bash
cd ~/RMS-Rover-v2 && source venv/bin/activate
python3 -m pi.tests.ugv01.test_slip
```

- **يفحص**: دوران بالمكان بسرعات 0.1 و0.2 و0.3 م/ث، خمس لفّات لكل سرعة (2ث، اتجاه متناوب). في كل عيّنة:
  `ω_enc = (R−L)/0.141` · `ω_gyr = gz·π/180` · `slip = |ω_enc − ω_gyr|` + الفارق الزمني بين T:1001 وT:1002.
  يطبع جدولاً لكل سرعة: متوسط الانزلاق · σ بين العيّنات · σ بين اللفّات · |ω_enc| · |ω_gyr| · Δt.
- **الروبوت**: 🔴 **على الأرض**، مساحة خالية (نصف متر حوله على الأقل)، أرضية الاستعمال الفعلي.
- ⚠ **أرقام فقط** — لا معامل ولا اقتراح. والقراءتان من لحظتين مختلفتين: جزء من «الانزلاق» قد يكون فارق زمن (يعالجه تعديل الفيرموير).
- **GO**: كل سرعة لها عيّنات استقرار، والإنكودر يرى دوراناً، وإشارتا ω_enc وω_gyr متوافقتان في الأغلبية.
- **NO-GO**:
  - «الإشارة متعاكسة» ⇒ اصطلاح إشارة الجايرو يعاكس الإنكودر؛ الرقم بلا معنى حتى يُحسم. **لا تقلب شيئاً** — أرسل الخرج.
  - «ω_enc ≈ 0» ⇒ عُد إلى الخطوة 5.
  - تحذير «تسطّح gz» ⇒ الجايرو مشبَع عند تلك السرعة؛ أرقامها ناقصة (أعد بـ`--speeds 0.1,0.2` وأرسل الاثنين).
- **CSV**: `logs/slip_*.csv` (كل العيّنات مع عمود `phase`) — **أرسل الملف كاملاً** + الجدول [4] + كتلة الحكم.
