# بروتوكولات RadiationRover — المرجع الكامل

> أي ميزة جديدة تُبنى **فوق** هذه البروتوكولات، لا بدلها. عند أي تعديل حدّث هذا الملف في نفس الجلسة.

## 1. أوامر الحركة النصية (البروتوكول الأساسي)

سطر نصي منتهي بـ`\n`:

| الأمر | المعنى |
|-------|--------|
| `F` / `B` / `L` / `R` | أمام / خلف / يسار / يمين بقوة افتراضية (75 على الأردوينو) |
| `S` | توقف |
| `F80` | حركة بقوة محددة 1-100 (ينطبق على F/B/L/R) |

**تصليب البارسر (الأردوينو):** يُقبل الأمر فقط إذا: الطول ≤ 4 أحرف، أول حرف من `FBLRS`، وكل ما بعده أرقام. أي سطر آخر (مثل رسائل إقلاع ESP32-CAM على الـSerial المشترك) يُتجاهل تماماً ولا يحدّث مهلة الأمان.

**مهلة الأمان:** الأردوينو يتوقف ذاتياً إذا لم يصل أمر خلال 1.5 ثانية.

**مزلاج الأمر اليدوي (الهَب):** الهَب يخزّن آخر أمر حركة **ويكرّره للكام من حلقته الموثوقة كل 250ms** — فلا تعتمد استمرارية القيادة على مؤقّت المتصفح (الذي يتلعثم تحت حمل الكاميرا فيسبب توقفاً/تقطّعاً). المتصفح يرسل الأمر مرة عند الضغط ثم keep-alive كل 300ms لتجديد المزلاج، و`S` عند الرفع (تُكرَّر لضمان التوقف). المزلاج ينتهي إن لم يصل تحديث خلال `MANUAL_LATCH_EXPIRE_MS` (أمان: توقّف المتصفح/انقطاعه). لورا (الشاشة) heartbeat كل 500ms.

## 2. مسار الأمر

```
واجهة الويب ──WS /ws──► الهَب ──UDP 4210──► ESP32-CAM ──Serial 115200──► Uno
```

- الهَب يقبل من WebSocket: أوامر حركة نصية كما هي، أو رسائل تحكم JSON (§5).
- أولوية القنوات: **لورا يدوي > WiFi > ذاتي**. أمر يدوي يقاطع فوراً أي مسح ذاتي أو تراجع سلامة جارٍ.
- **قناة لورا نصف-مزدوجة**: الهَب **يوقف بثّ حالته** (`LORA_QUIET_AFTER_RX_MS`) بعد أي أمر لورا يدوي حتى لا يزاحم الأوامر على القناة ويؤخّر الاستجابة.

### 2.1 تيليمتري الأردوينو (الاتجاه العكسي على نفس Serial)

الأردوينو يرسل أسطراً نصية منتهية بـ`\n` على Serial المشترk، والكام تمرّرها إلى الهَب عبر UDP 4212:

| السطر | كل | المعنى |
|-------|-----|--------|
| `BV:7.85` | 2s | جهد البطارية (فولت) |
| `OBS:34.5,0,1` | 200ms | مسافة الفوق-صوتي الأمامية سم (`-1`=خالٍ) ثم IR يسار ثم IR يمين (0/1) |

الأردوينو يقرأ الحساسات ويبلّغ فقط — **كل القرارات في الهَب**. لا محاكاة: عند غياب الأسطر تُبلَّغ حالة "لا بيانات".

## 3. منافذ UDP

| المنفذ | الاتجاه | المحتوى |
|--------|---------|---------|
| 4210 | هَب → كام | أوامر حركة نصية |
| 4211 | — | منفذ الإرسال المحلي على الهَب |
| 4212 | كام → هَب | تيليمتري الأردوينو: بطارية `BV:7.85` وعوائق `OBS:<سم>,<L>,<R>` (المسافة -1 = خالٍ). **قبل أن تعرف الكام عنوان الهَب تبثها broadcast على subnet**، والهَب يتعلم IP الكام من أول حزمة (تعارف ذاتي بالاتجاهين) |
| 4220 | هَب → شاشة | تيليمتري JSON broadcast كل ثانية (§6) |

## 4. رسائل WebSocket من الهَب للواجهة (كلها JSON بحقل `t`)

| `t` | متى | الحقول |
|-----|-----|--------|
| `hello` | عند الاتصال | — |
| `gps` | كل 1s | `fix,lat,lng,sat,spd,hdg,alt` (الـhdg من الـIMU) أو `fix:false,sat` |
| `batt` | كل 2s | `v` (فولت) |
| `rad` | كل 1s | `cpm1,cpm2,cpm,usvh,risk,lvl(0-4),anom,calib(%،-1=لا معايرة),mission,scan,scanpct,retreat,sim` + عوائق: `obs`(سم أمامي),`obl`/`obr`(IR يسار/يمين 0/1),`obh`(صحة 0-2),`obk`(عائق حاجز 0/1) |
| `anomaly` | فور كشف شذوذ | `cpm,usvh,lat,lng` |
| `alarm` | عند Critical | `usvh,msg:"critical_retreat"` |
| `scan` | عند انتهاء مسح 360° | `ok,dir,conf` |
| `report` | عند إنهاء المهمة | `data:{...}` (§7) |
| `info` | أحداث عامة | `msg` (`mission_started`, `logger_fail`, `estop`...) |

## 5. رسائل التحكم JSON من الواجهة للهَب

`{"c":"<command>"}` حيث command واحدة من:

- `mission_start` — بدء مهمة: ملف CSV جديد + معايرة خلفية 60 ثانية
- `mission_end` — إنهاء المهمة وبث التقرير وحفظه
- `scan_start` / `scan_cancel` — مسح دوراني 360°
- `estop` — إيقاف طوارئ (يلغي كل شيء ذاتي ويوقف)

(المرحلة A3 ستضيف حفظ خطط المهمات JSON الكاملة.)

## 6. تيليمتري الشاشة (UDP 4220)

JSON واحد كل ثانية. الحقول الأصلية: `fix,lat,lng,sat,spd,hdg,alt,bv` (أو `fix:0,sat,bv`). أضيفت فوقها (إضافة متوافقة): `cpm,usvh,risk,obs`(مسافة العائق الأمامي سم).

## 7. تقرير المهمة (JSON)

```json
{
  "duration_s": 0, "distance_m": 0.0,
  "max_usvh": 0.0, "max_risk": "Safe",
  "max_pos": {"lat": 0, "lng": 0},
  "anomalies": 0,
  "source":   {"found": false, "dir_deg": -1, "confidence": 0},
  "gradient": {"found": false, "dir_deg": -1, "slope_usvh_per_m": 0},
  "danger_zones": [{"lat": 0, "lng": 0, "usvh": 0}],
  "recommendations": ["نص عربي..."]
}
```

يُحفظ كـ`/MRPT_NNN.json` بجانب `/LOG_NNN.csv` (LittleFS الآن، SD لاحقاً).

## 8. صيغة CSV للتسجيل

```
ms,lat,lng,fix,cpm1,cpm2,cpm,usvh,risk,heading,anomaly
```

سطر كل ثانية أثناء المهمة. `risk` نص (Safe/Low/Medium/High/Critical)، `anomaly` 0/1.

## 10. تحويلات وعتبات (المرجع: config.h)

- µSv/h = CPM ÷ 123 (قابل للمعايرة — `CPM_PER_USVH`)
- المستويات: Safe <0.5 | Low 0.5-2 | Medium 2-10 | High 10-100 | Critical >100 µSv/h
- الشذوذ: قراءة دلو 10 ثوانٍ > μ+3σ (معايرة 60 ثانية عند بدء المهمة)
- Critical ⇒ تراجع تلقائي ~2م (5 ثوانٍ بقوة 60) + إنذار — طبقة سلامة محلية خارج أي AI
