# BRIEF الدفعة الثانية الموحّدة: القيم المعايرة + الجسر الحقيقي + الواجهة

متابعة لمشروع RMS Rover v2. **وصل Wave Rover واكتملت معايرته على العتاد الحقيقي.** هذه الدفعة تدمج ثلاثة أشياء: تثبيت القيم المقاسة، كتابة جسر الروفر الحقيقي، وبناء الواجهة الحية.

**البطارية قيد الشحن الآن** — فكل ما يخص العتاد يُكتب الآن ويُختبر لاحقاً، والواجهة تُبنى وتُختبر فوراً على المحاكاة.

---

## أ) القيم المعايرة على العتاد — ثبّتها في `config.py` ووثّقها

هذه أرقام **مقاسة تجريبياً**، لا افتراضات. أي انحراف عنها يكسر السلوك:

### أ-1) الحركة والاتجاه

| القيمة | الرقم | المصدر |
|---|---|---|
| `MOTOR_INVERT` | **-1** | ⚠ الاتجاهات معكوسة في العتاد: L/R موجب يعني للخلف. اضرب كل أمر حركة في -1 |
| `GYRO_SCALE` | **0.9093** | معامل تحويل معاير (لفّة 90° مقدّرة = 94° فعلية قبل التصحيح) |
| `TURN_POWER` | **0.40** | يكفي للدوران بالمكان على السيراميك |
| `DRIVE_POWER_DEFAULT` | **0.50** | سرعة المهمة (≈0.60 م/ث) |
| سرعة عند 0.3 | 0.333 م/ث | معايرة سيراميك، بطارية منخفضة — **تُعاد بعد الشحن** |
| سرعة عند 0.5 | 0.600 م/ث | نفس الشرط |
| قوة 0.7 | **غير موثوقة** | انزلاق + هبوط جهد — لا تستخدمها للملاحة |

### أ-2) قرار معماري حاسم: الاتجاه من تكامل الجايرو (لا من البوصلة)

**وثّق هذا في `CLAUDE.md` كقرار ملزم.** السبب: هيكل Wave Rover معدني كامل وحوله أربعة محركات بمغانط، فالمغنيتومتر (البوصلة) يقرأ مجال الروبوت نفسه ويدور معه. **اختبار مثبت**: لفّتان متتاليتان بنفس الاتجاه أعطتا +35.9° ثم −35.3° (تأرجح، لا تتبّع).

الحل المعتمد:
```
heading += (gz - bias) * dt * GYRO_SCALE
```
- `gz` من رسالة `T=126`.
- **`bias` يُقاس تلقائياً عند بدء كل مهمة** (4-5 ثوانٍ والروبوت ساكن) — **لا تثبّته في الكود**، فقد تغيّر بين التجارب (-0.218 ثم -0.358).
- الجايرو مناعته تامة ضد المعدن والمحركات؛ انجرافه في لفّة 3 ثوانٍ مهمل، وتصحيح الجدران يمسح أي تراكم.
- BNO055 يبقى مدعوماً خلف علم كبديل، لكنه **ليس المصدر الافتراضي**.

### أ-3) عتبات الجهد — حماية إلزامية

تُقرأ من الحقل `v` في رسالة `T=130` باستمرار:

| الجهد | الحالة | الإجراء التلقائي |
|---|---|---|
| > 11.5V | ممتاز | تشغيل طبيعي |
| 10.8 – 11.5V | جيد | تنبيه خفيف في الواجهة |
| 10.2 – 10.8V | منخفض | **RTH إجباري** |
| < 10.0V | حرج | **إيقاف المحركات فوراً** + إنذار |

سياق: بطارية 3S (اسمي 11.1V، ممتلئة 12.6V). سُجّل هبوط إلى 8.98V أثناء الاختبار — لا يتكرر بعد هذه الحماية. اعرض الجهد ونسبة تقديرية في الواجهة دائماً.

### أ-4) المنافذ النهائية الفعلية — حدّث `docs/wiring.md`

| المكوّن | التوصيل | ملاحظة |
|---|---|---|
| Wave Rover | `/dev/serial0` @115200، JSON سطري | عبر هيدر 40-pin |
| جيجر | **BCM21 (دبوس 40)**، `RISING_EDGE`، **`SET_PULL_NONE`** (عائم) | أي pull يقتل الإشارة · 📜 كان BCM17 |
| IR أمامي أيسر | BCM25 (دبوس 22)، تغذية 3.3V | **0 = عائق** |
| IR أمامي أيمن | BCM16 (دبوس 36)، تغذية 3.3V | **0 = عائق** |
| ألترا سونيك TRIG | BCM23 (دبوس 16) | مباشر |
| ألترا سونيك ECHO | BCM24 (دبوس 18) | ⚠ عبر مقسّم جهد (1kΩ/2kΩ) |
| BNO055 | I2C **0x29** | احتياطي |
| الكاميرا | `/dev/video0` | 640×480 |
| GPS | ⚠ **متعارض مع الروفر على serial0** | الحل: محوّل USB-Serial، أو تعطيله داخل المباني |

**ملاحظة موضع الحساسات**: حساسا IR في الركنين الأماميين (لا الجانبين) — كلاهما يراقب الأمام بزاوية. منطق التفادي: عائق أمام-يسار → لفّ يميناً، أمام-يمين → لفّ يساراً، كلاهما أو أمامي مركزي → رجوع + لفّ 90°.

### أ-5) المعايرة: نظام لا أرقام ثابتة

- ملفات معايرة لكل أرضية (سيراميك/موكيت/قاعة العرض) عبر `calibration.py` الموجود.
- **الأرقام أعلاه أُخذت تحت بطارية منخفضة** — أضف زر "إعادة معايرة" في الواجهة، وسجّل **جهد البطارية وقت المعايرة** في ملف المعايرة (مؤشر على صلاحيتها).
- إن كان فارق الجهد بين المعايرة والتشغيل > 1V، أظهر تحذيراً "المعايرة قد تكون غير دقيقة".

## ب) جسر الروفر الحقيقي — `pi/rover/bridge.py`

واجهة موحّدة بوضعين `sim` / `real`، والتبديل بعلم واحد. **بروتوكول Waveshare المكتشف تجريبياً:**

**الإرسال** (JSON سطري + `\n` على `/dev/serial0` @115200):
```python
{"T": 1, "L": <-1..1>, "R": <-1..1>}   # حركة — تُضرب في MOTOR_INVERT
{"T": 126}                              # طلب IMU كامل
{"T": 130}                              # طلب حالة مختصرة
```

**الاستقبال:**
```python
# رد T=126 →
{"T":1002, "r":.., "p":.., "y":.., "ax":.., "ay":.., "az":..,
 "gx":.., "gy":.., "gz":.., "mx":.., "my":.., "mz":.., "temp":..}
# رد T=130 →
{"T":1001, "L":.., "R":.., "r":.., "p":.., "y":.., "temp":.., "v":..}
```

**ملاحظات تنفيذية مثبتة:**
- الفيرموير **يردّد الأمر المُرسل صدىً** قبل الرد الفعلي — تجاهل أي سطر يطابق ما أرسلته، وانتظر `T:1002` أو `T:1001`.
- استخدم `y` (yaw) **للعرض فقط لا للملاحة** (البوصلة غير موثوقة). الملاحة من `gz`.
- `T=131`, `T=4`, `T=71` بلا رد — لا تعتمد عليها.
- **الأمر المرتد لا يعني التنفيذ** — تحقق من الحركة عبر `gz`/التسارع لا عبر الصدى.

**الوظائف المطلوبة:** `forward/backward/turn/stop`، `read_imu()`, `read_status()`، `calibrate_gyro_bias()`، `turn_by_angle(deg)` بتكامل الجايرو مع مهلة أمان 8 ثوانٍ، ومراقبة الجهد المستمرة مع تطبيق عتبات أ-3.

**heartbeat وأمان**: مهلة 1.5 ثانية بلا أوامر → إيقاف المحركات. أي استثناء في الحلقة → `stop()` في `finally`.

## ج) الواجهة الحية — تُبنى وتُختبر على المحاكاة الآن

**شرط أساسي: تعمل على ويندوز بلا راسبري وبلا عتاد** (التطوير يجري على اللابتوب، الراسبري قد يكون مطفأً).

### ج-1) التوافق مع ويندوز — قبل أي شيء
1. **لا استيراد لمكتبة عتاد على مستوى أي وحدة**. كل استيراد داخل دالة أو خلف:
   ```python
   HARDWARE_AVAILABLE = False
   try:
       import lgpio
       HARDWARE_AVAILABLE = True
   except ImportError:
       pass   # بيئة تطوير — محاكاة
   ```
2. غياب مكتبات العتاد → `SIMULATION_MODE=True` إجبارياً + لافتة واضحة في الواجهة: "وضع المحاكاة — لا يوجد عتاد متصل". لا فشل صامت.
3. `requirements-dev.txt` منفصل (fastapi, uvicorn, websockets, numpy) **بلا أي مكتبة عتاد**.
4. `pathlib` لكل المسارات. وقسم "التشغيل على ويندوز" في README بأوامر PowerShell.

### ج-2) السيرفر — `pi/web/server.py`
FastAPI + WebSocket على 8000. يقود وحدات `pi/nav/` عبر `sim_world.py`. حلقة محاكاة مع **مضاعف سرعة (×1/×5/×20)**. بث كل ~200ms: الموقع، heading، نصف قطر عدم اليقين، الخلايا المتغيّرة، المسار، القراءة، الجهد، التغطية.

### ج-3) الواجهة — ثيم داكن، عربية RTL، **بلا أي CDN**
1. **إعداد الغرفة**: طول×عرض، ركن الانطلاق (4 أزرار)، تباعد، اختيار ملف المعايرة.
2. **خريطة الشبكة الحية** (canvas — جوهر الواجهة): خلايا ملونة بمستوى الخطر/غير مزارة/محجوبة/غير قابلة للوصول/ذات أولوية • الروبوت كمثلث باتجاه heading + **دائرة عدم اليقين** • المسار المخطط والمقطوع • علامات الشذوذ.
3. **لوحة الحالة**: التغطية بالرقمين (نسبة + عدد قابل للوصول/محجوب)، الموقع (x,y)، heading، نصف قطر عدم اليقين، عدد التصحيحات، µSv/h ومستوى الخطر، **جهد البطارية بلونه**، زمن المهمة.
4. **لوحة الحساسات**: مسافة الألترا سونيك حية، حالة IR أمامي-يسار/يمين، CPM.
5. **أزرار (لا كونسول إطلاقاً)**: بدء مسح، إيقاف مؤقت، استئناف، **إيقاف طوارئ بارز دائماً**، عودة للانطلاق، مضاعف السرعة، معايرة سرعة، معايرة انحياز الجايرو.
6. **أداة اختبار**: النقر على خلية يضع/يزيل عائقاً وهمياً → مشاهدة إعادة التخطيط ترسم مساراً بديلاً فوراً.
7. رسم CPM زمني + سجل أحداث جانبي (بدء، تصحيح جدار، عائق، إعادة تخطيط، شذوذ، تحذير بطارية).

## د) معايير القبول

**على ويندوز (فوراً):**
- [ ] clone + `pip install -r requirements-dev.txt` + أمر تشغيل واحد → الواجهة تعمل. لا حاجة للراسبري.
- [ ] لافتة "وضع المحاكاة" ظاهرة، بلا أخطاء مكتبات مفقودة.
- [ ] غرفة 4×3م → شبكة ومسار مرسومان → "بدء مسح" → الروبوت يتحرك والخلايا تتلون حتى 100%.
- [ ] النقر على خلية أثناء المسح → عائق → **مسار بديل يُرسم فوراً**.
- [ ] دائرة عدم اليقين تكبر بالحركة وتصغر عند تصحيح جدار.
- [ ] مضاعف ×20 ينهي مسح غرفة في ثوانٍ.
- [ ] لا استيراد لمكتبة عتاد على مستوى أي وحدة (تحقق بالبحث).

**على الراسبري (بعد اكتمال الشحن):**
- [ ] `bridge.py` وضع `real`: أمر تقدّم يحرّك الروبوت **للأمام فعلاً** (تحقق `MOTOR_INVERT`).
- [ ] `turn_by_angle(90)` يلفّ 90° ±8°.
- [ ] معايرة الانحياز التلقائية تعمل عند بدء كل مهمة.
- [ ] جهد البطارية يظهر في الواجهة، وهبوطه تحت 10.2V يفعّل RTH تلقائياً.
- [ ] فقدان الاتصال بالروفر > 1.5 ثانية → إيقاف المحركات.
